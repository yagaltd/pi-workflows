# DEC-003: tdd-guard via agent-spec's tdd-guard layer is the build-task test-quality gate

> Status: active
> Decided-by: 20260924-013
> Amended-by: 20261117-064 (owner-approved: the gate must name only tools that exist)
> Scope: agents/**, skills/**, extensions/index.ts, scripts/flow-gates.mjs
> Revisit when: tdd-guard covers gaming, weakening or drift checks, or a benchmark shows the uncovered classes ship defects

Rule: Build tasks gate on `agent-spec lifecycle <spec> --code . --layers lint,boundary,test,tdd-guard` — the tdd-guard layer already exists in agent-spec (`src/spec_verify/tdd_guard_verifier.rs` runs `tdd-guard --version` then `tdd-guard lint`); a standalone run is `tdd-guard lint` / `tdd-guard verify --spec <spec>`.

The `tdd:` task flag keeps its meaning: it routes the task through the
two-phase TDD shape and enables the same chain as the task gate. The
previous decision named a standalone test-quality binary that was never
installable (npm 404, no GitHub project, absent from PATH), so every
emitter pointed at a command that could not run. The gate now names only
tools that exist: agent-spec's tdd-guard layer plus the tdd-guard CLI it
invokes.

Accepted risk (owner-approved at the 20261117-064 gate): gaming, weakening
and drift checks stay uncovered. tdd-guard remains the deterministic gate
(`lint` fails skipped, assertionless, internally mocked and
implementation-coupled tests; `verify` fails when tests do not cover the
spec's decisions, boundaries or `Test:` selectors). The tradeoff is the one
already recorded in `.workflows/proposals/20261024-test-quality-cli.md`.
An absent tdd-guard is never a silent pass: agent-spec returns SKIP for
every scenario and the skip is stated loudly (dispatch text, LOG.md, gate
output). Verdict semantics are unchanged — only a reviewer verdict
`ok:true` closes a task.
