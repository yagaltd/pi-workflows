# DEC-007: Requirement-block import is deferred — the command does not exist

> Status: active
> Decided-by: 20261117-064
> Scope: prompts/idea.md, prompts/brainstorm.md, tests/intake/README.md, docs/architecture.md, tests/intake/rendered
> Revisit when: an import command ships and runs in the installed agent-spec binary (verified as `agent-spec 0.2.7` having no `requirements` subcommand on 2026-11-17)

Rule: `/idea` and `/brainstorm` were documented as emitting marked requirement blocks and then running `agent-spec requirements import --from <file> --check --out .workflows/requirements/`, but no such command exists anywhere it could run: installed agent-spec 0.2.7 rejects it (`error: unrecognized subcommand 'requirements'`), the clone at `~/Documents/github/agent-spec` has no marked-block parser, and the fork the docs cite (`~/Documents/vibe/coding-agent/agent-spec`) is gone from disk — so the instruction was removed, not the format. Both prompts keep emitting candidate blocks to `.workflows/intake/<date>-<slug>.md` and stop at the human approval gate, stating plainly that the import step is deferred because the command does not exist and that nothing was imported; `tests/intake/README.md` keeps the marker/attribute/id-validation documentation as a FORMAT RECORD — the specification a future implementation must satisfy — and labels `sample-intake.md` + `rendered/` pinned examples rather than a passing check. No doc may present the import as a live step until the revisit trigger fires; implementing an importer or inventing a replacement format is out of scope for this deferral.
